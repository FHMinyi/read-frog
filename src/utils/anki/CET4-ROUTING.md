# CET4 分流需求与实现取舍

修改日期：2026-10-11。

本次修改让符合条件的新词直接进入 `cet4` 牌组，并提供独立的旧卡整理入口。新卡分流与旧卡整理均由用户主动选择。本文与核心实现 `engine.ts` 同级，记录需求、实现理由、行为边界和验收状态；同时记录本次交付脚本取消旧包备份的调整。

## 需求与确认

- 用户希望 CET4 及以下词汇进入 `cet4`，而非默认牌组；不得在两个牌组各存一份。
- 经用户确认，当前判定口径为“命中已有 CET4 词表”，包含 CET4。词表归属不等于完整的难度评分，不能承诺覆盖所有比四级简单的词。
- 新卡分流是可选项；旧卡整理也是独立可选操作，不能因开启分流而自动移动旧卡。
- 用户要求后续本地交付不保留旧包备份，删除不再需要的旧逻辑，保持代码直接简洁。

## 行为与取舍

### 新卡直接选择目标牌组

`AnkiSettings.routeCet4` 默认 `false`，通过已有设置存储读取时合并默认值，旧设置不需要单独迁移。

启用后，只有已确认的普通单词身份（`word:`）且词元命中内置 CET4 词表，才选择 `cet4`。其他条目使用默认牌组。复用已有词形归一化和词表查询，不新增 AI 难度判断、在线查询或通用规则引擎：当前需求只有一条明确规则，复用本地数据便于复现，也避免额外请求。

短语、专有名词和未确认词形不参与分流，即使其组成词或表面拼写命中词表，也不会据此推断难度。目标牌组固定为 `cet4`，当前未增加目标牌组和难度阈值配置。

新词在首次创建笔记时直接指定目标牌组，不先加入默认牌组再移动。改变分流开关或默认牌组，会更新尚未确认同步且没有笔记 ID 的本地待同步条目的目标；已存在的远端笔记继续合并例句，不自动改牌组。关闭分流不会撤回以前的分流结果。

### 旧卡通过独立按钮移动

旧卡整理是一次性手动操作，不是持久化的自动清理开关。它可独立于新卡分流开关和自动同步开关执行，但需要 AnkiConnect 可用。按钮使用已保存的默认牌组设置，不采用表单中尚未保存的编辑值。

整理直接从 Anki 获取 Read Frog 模型的笔记，再按实际牌组名精确筛选，不依赖当前浏览器的本地保存记录。使用固定模型查询，再读取实际牌组，避免将用户牌组名解释为搜索语法或误移子牌组卡片：

1. 验证模型、字段及卡片 ID，从保存的原句数据重新归一化词元和身份，并校验 `RFKey`、数据版本、身份及所有例句的一致性；不根据展示用 HTML 推断单词。
2. 要求笔记对应一张有效卡片；缺失或不兼容的数据不盲目处理。
3. 卡片已经位于 `cet4` 时，只校正本地牌组记录并计为跳过；卡片位于其他牌组时跳过，尊重用户的手工整理。
4. 仅将实际位于当前已保存默认牌组的卡片，通过 `changeDeck` 移到 `cet4`。
5. 再次读取实际牌组，确认成功后更新本地记录及成功数量。

此范围覆盖其他浏览器或旧安装环境创建的 Read Frog 卡片，不修改其他模型、其他牌组或子牌组中的卡片。代价是需要只读枚举 Read Frog 模型的笔记，集合较大时会增加查询时间。未命中 CET4、位于其他牌组和已在目标牌组的条目计为跳过；数据缺失或不兼容的条目报告失败。

本地有对应记录时更新其牌组；没有本地记录时只移动远端原卡，不创建本地同步记录，也不重新生成例句或音频。没有学习状态过滤，正在学习或复习不会阻止整理。

移动使用原卡片 ID，不创建或删除笔记，不重写字段、音频或复习数据。移动后后续学习仍由目标牌组的 Anki 设置管理。

### 失败与并发处理

整理与同步队列共用已有锁，避免它们同时处理同一卡片；没有另建任务调度层。逐条处理失败并返回词元和错误，其余条目继续处理。

若 Anki 已完成移动但响应丢失，本次会报告失败；再次手动运行时会读到卡片已在 `cet4`，修正本地记录，不重复建卡。若 Anki 没有实际保留移动结果，读回校验不会把它计为成功。

整理不进入自动重试队列，失败需再次点击按钮。扩展进程中断时，界面可能拿不到完整结果，再次运行会按远端实际归属判断。移动前检查端点和默认牌组是否改变，但 AnkiConnect 没有跨多次请求的事务保证，不能宣称消除了全部外部并发修改风险。

## 本地交付不保留旧包

相关代码为 [prepare-local-handoff.mjs](../../../scripts/prepare-local-handoff.mjs)。

脚本仍先验证扩展身份、权限、构建内容及复制后的文件哈希，再删除当前交付目录，将校验完成的临时目录改名为当前目录。删除了旧包备份目录生成、备份记录及失败回退逻辑。临时目录只用于交付准备，成功后成为当前目录，不额外保留一份副本；直接替换也避免上次构建的旧文件残留。

取舍是节省空间、简化交付逻辑，但删除当前目录之后若替换失败，不再自动恢复上一版，需要重新执行交付。异常中断可能留下临时目录，当前没有增加后台清理机制。

本次已删除 11 个历史扩展包备份目录及对应旧备份清单，释放约 280 MiB；当前使用的 `handoff/chrome-mv3` 保留。

## 旧卡扫描范围修正

用户发现带有 CET4 标签的 `passion` 仍在 `陪读蛙`。只读核实表明：Anki 中身份为 `word:passion`，词表条件符合，但当前浏览器的六条本地记录没有该词。初版仅遍历本地记录，因而漏掉该卡，与复习状态无关。

用户确认旧卡整理应直接扫描 Anki 默认牌组，因此移除本地记录前置条件。回归测试使用两个独立的本地数据库共享同一个模拟 Anki：第一个环境创建 `passion`，第二个环境没有本地记录。旧实现返回移动 0 张而测试失败，修正后返回移动 1 张，同时保持原笔记和卡片 ID、不新增本地条目、不调用制卡或语音生成。

修正后相关测试 167 项通过，4 项真实服务测试跳过；另覆盖了没有本地记录时的数据损坏、非 CET4 词汇、子牌组和手工牌组保护。类型检查、格式检查、差异检查及本地构建通过，交付目录已更新且没有生成旧包备份。本次没有执行真实旧卡移动，仍需重新加载扩展后由用户点击整理入口验收。
